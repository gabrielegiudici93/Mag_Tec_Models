\begin{abstract}
This report documents the workflow implemented in the \texttt{Mag\_Tec\_Models} repository for
evaluating a single indentation point on the MagTec soft tactile skin under multiple stretch
conditions. The goal is to quantify the relationship between magnetic Hall-effect sensor
signals and applied forces, and to assess classification models for contact location and skin
stretch. The document details the hardware protocol, data acquisition code, feature
extraction, baseline machine-learning models, and Key Performance Metric (KPM)
calculations. The tables below reflect the latest acquisition run and are populated directly from the JSON metrics reports generated by \texttt{train\_unified.py}.
\end{abstract}

\section{System Overview}

\subsection{Hardware Stack}
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Soft tactile skin:} Silicone sheet embedding 15 Hall-effect sensors arranged
          as a \(3 \times 5\) grid (15 sensors, 3 magnetic channels per sensor).
    \item \textbf{Magnets:} One permanent magnet sits above each sensor. When pressed,
          the magnet displacement changes the measured magnetic flux components.
    \item \textbf{Indenter:} Mechanically coupled to a 6-axis force/torque (FT) sensor mounted
          on the Franka Emika Panda end-effector.
    \item \textbf{Robot:} Franka Emika Panda controlled via \texttt{pyfranka\_interface}.
\end{itemize}

\section{Data Acquisition Protocol}

\subsection{Press Grid}
The study targets a single central position (\texttt{TARGET\_POSITION\_ID = 32}) at coordinates
\[
    \text{TARGET\_POSITION\_COORDS} = [0.495774, 0.440503, 0.034311] \text{ m},
\]
together with four neighbour offsets \(\{\text{NW}, \text{NE}, \text{SE}, \text{SW}\}\), plus the centre. Baseline offsets
are defined by the constants
\[
    \text{BASE\_NS\_OFFSET} = 2.5 \text{ mm}, \qquad
    \text{BASE\_EW\_OFFSET} = 5.0 \text{ mm},
\]
which correspond to the spacing between neighbouring magnets in the unstretched configuration. The offset directions are:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{NE (nord-est):} \([-2.5, +5.0, 0]\) mm
    \item \textbf{NW (nord-ovest):} \([-2.5, -5.0, 0]\) mm
    \item \textbf{SE (sud-est):} \([+2.5, +5.0, 0]\) mm
    \item \textbf{SW (sud-ovest):} \([+2.5, -5.0, 0]\) mm
\end{itemize}

\subsection{Stretch Configurations}
The skin is tested at three longitudinal stretches (default values):
\[
    \mathcal{S} = \{0.00, 0.10, 0.20\}.
\]
For any stretch \(s \in \mathcal{S}\), offsets along the horizontal axis are scaled by
\((1+s)\), while vertical offsets remain unchanged (magnet layout is elongated only along the
horizontal direction). Data for each stretch level are stored as separate HDF5 files within each run directory:
\begin{center}
\texttt{force\_0.0to3.0N\_step0.1N\_single\_testX\_stretch\_000pct.h5}, \texttt{force\_0.0to3.0N\_step0.1N\_single\_testX\_stretch\_010pct.h5}, \texttt{force\_0.0to3.0N\_step0.1N\_single\_testX\_stretch\_020pct.h5}
\end{center}

Each acquisition session is stored in its own run directory. The scripts generate

    \texttt{Multiple\_Points/force\_0.0to3.0N\_step0.1N\_single\_testX/} & \text{multi-point runs}

\]
Within each run directory the three stretch recordings are saved as individual HDF5 files
(\texttt{\_stretch\_000pct.h5}, \texttt{\_stretch\_010pct.h5}, \texttt{\_stretch\_020pct.h5}).

\subsection{Cleaned Dataset Structure}
After data collection, the cleaning and training pipeline creates a \texttt{cleaned/} subdirectory with the following organized structure:
\[
\texttt{cleaned/}\begin{cases}
    \texttt{data/} & \text{Cleaned HDF5 files (test\_XX\_YYY\_cleaned.h5)}\\
    \texttt{raw/} & \text{Raw feature models and plots}\\
    \quad \texttt{models/} & \text{Trained models (\texttt{*.joblib} files) and JSON metrics}\\
    \quad \texttt{plots/} & \text{Training plots (confusion matrices, prediction scatter, residuals)}\\
    \quad \quad \texttt{sim/} & \text{Simulation-specific plots (if simulation data)}\\
    \quad \quad \quad \texttt{stretch\_XXXpct/} & \text{Raw data plots per stretch level}\\
    \texttt{raw\_data/} & \text{Raw data visualization plots (real data only)}
\end{cases}
\]
The cleaned dataset structure is designed to keep all processed data, models, and visualizations organized in a single location. The \texttt{data/} subdirectory contains the cleaned HDF5 files with simplified naming: \texttt{test\_XX\_YYY\_cleaned.h5}, where \texttt{XX} is the test number (e.g., 50) and \texttt{YYY} is the stretch level (000, 010, 020). The \texttt{raw/} subdirectory contains all trained models (force regressors, offset classifiers, stretch classifiers, and scalers) and model performance visualizations (confusion matrices, prediction scatter plots, residual plots). For simulation data, raw data plots are saved in \texttt{raw/plots/sim/stretch\_XXXpct/} to distinguish them from real data plots. The \texttt{raw\_data/} subdirectory contains raw data visualization plots for real data, organized by stretch level (\texttt{raw\_data/stretch\_XXXpct/}).

\subsection{Calibration and Logging}
\begin{enumerate}[leftmargin=1.5em]
    \item Both FT and StretchMagTec streams must provide live data before any calibration is
          attempted. The code waits up to \SI{60}{\second} for StretchMagTec and \SI{30}{\second}
          for the FT sensor.
    \item \textbf{Initial calibration position:} The robot first moves to a position \SI{5}{\milli\metre} above the target center position for calibration. After calibration, it moves to the exact center position before starting data collection.
    \item After the first frame, the script enforces an additional \SI{15}{\second}
          stabilisation period before measuring offsets for StretchMagTec and \SI{3}{\second}
          for the FT sensor.
    \item Continuous logging (raw sensor stream and FT data) is saved to the HDF5 datasets
          \texttt{stretchmagtec}, \texttt{forces}, \texttt{positions}, \texttt{timestamps},
          and \texttt{labels}.
    \item Each complete press sequence (from \texttt{\_sequence\_start} to \texttt{\_sequence\_end} labels)
          is saved as a separate entry in the \texttt{presses} group, containing:
          \begin{itemize}
              \item \texttt{forces}: Force/torque data for the entire sequence,
              \item \texttt{stretchmagtec}: \(15 \times 3\) magnetic channels for all samples,
              \item \texttt{positions}: Robot position data \([x, y, z]\) for all samples,
              \item \texttt{indentation}: Relative Z displacement from initial position (negative values indicate indentation),
              \item \texttt{timestamps}: Normalized timestamps starting from 0 seconds,
              \item \texttt{labels}: Sequence labels.
          \end{itemize}
          Each press entry includes metadata attributes: \texttt{press\_id}, \texttt{offset}, \texttt{stretch\_level},
          \texttt{initial\_z}, and \texttt{max\_indentation}.
    \item At the end of every press cycle, the script also captures a snapshot consisting of:
          \begin{itemize}
              \item \(15 \times 3\) magnetic channels,
              \item \(3\) force components (Fx, Fy, Fz) plus torques,
              \item Metadata (press ID, stretch level, offset key, press depth, timestamp).
          \end{itemize}
          These records are stored in the
          \texttt{press\_summaries/\{sensors, forces, metadata\}} datasets to streamline the ML
          pipeline.
\end{enumerate}
All file attributes include the stretch label, press profile, and pressing parameters so the
analysis script can reconstruct the acquisition context without external configuration files.

\section{Feature Extraction and Data Processing}

\subsection{Tactile Features}
For each sample in a press sequence, the 15 sensors are flattened into a \(45\)-length vector:
\[
    \mathbf{s}_{\text{raw}} = \left[\begin{array}{cccc}
        S_{1x} & S_{1y} & S_{1z} & \dotsc S_{15z}
    \end{array}\right]^T.
\]
\textbf{No feature engineering is applied:} the models use only the raw 45 magnetic features (15 sensors \(\times\) 3 channels). This approach simplifies the pipeline and ensures that the models learn directly from the sensor measurements without additional transformations. After flattening, the 45 features are normalized using \texttt{StandardScaler} from scikit-learn (zero mean, unit variance).


\subsection{Data Processing Pipeline}
The training pipeline applies several preprocessing steps to ensure robust model performance:

\subsubsection{Feature Normalization}
All magnetic features are normalized using \texttt{StandardScaler} from scikit-learn, which standardizes features to have zero mean and unit variance. This normalization is applied globally across all training sequences to ensure consistent scaling.

\subsubsection{Displacement Filtering}
To remove noise and artifacts, samples with high consecutive displacement are filtered out. The filtering is applied independently to:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Magnetic data:} Samples where consecutive magnetic field readings show displacement above the 95th percentile threshold are removed.
    \item \textbf{Force data:} Samples where consecutive force readings show displacement above the 95th percentile threshold are removed.
\end{itemize}
The two sensors are treated independently, ensuring that artifacts in one sensor do not affect the other. The default displacement threshold is \SI{95}{\percent}.

\subsubsection{Force Processing}
Instead of normalizing force values, sequences are \emph{cut} at 3~N: all samples where \(F_z > 3.0\)~N are removed from the sequence. This approach preserves the original force distribution while ensuring that all sequences are limited to the target force range. The original force range \([F_{z,\min}, F_{z,\max}]\) is stored as part of the model metadata (fz\_scaler) for reference. For simulation data, where forces are negative (0 to -3~N), absolute values are used during training, and the negative sign is restored during plotting.

\subsubsection{Outlier Removal}
The outlier removal process consists of two steps:
\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{First sequence removal:} The first sequence per offset is removed to eliminate warm-up/calibration effects. This ensures that all sequences used for training and analysis are from stable, calibrated sensor states.
    \item \textbf{Outlier removal:} Sequences with anomalous characteristics are removed using Median Absolute Deviation (MAD) outlier detection. The outlier removal process is applied \emph{independently for each offset position} (center, nw, ne, se, sw), ensuring that outlier detection is tailored to the specific characteristics of each press location. For each offset, the two most extreme outlier sequences are removed based on the following metrics:
          \begin{itemize}[leftmargin=1.5em]
              \item Sequence duration (outliers in temporal length, weighted 1.5\(\times\) in the combined score)
              \item Maximum force \(F_z\) (outliers in force magnitude)
              \item Number of samples (outliers in sequence length)
          \end{itemize}
          Outlier detection uses a Z-score threshold of 3.0, and the two sequences with the highest combined outlier scores are removed per offset. Duration is given higher weight (1.5\(\times\)) in the combined score to catch sequences that are significantly longer or shorter than the median. This per-offset approach ensures that each press location is evaluated independently, preventing outliers in one location from affecting the analysis of another. The same outlier removal procedure is applied both during model training and before plot generation to ensure consistency between analysis and visualization.
\end{enumerate}

\subsubsection{Dataset Balancing}
To ensure fair comparison across stretch levels, sequences are balanced so that each stretch level contributes an equal number of sequences to the training set. This prevents bias toward stretch levels with more data.

\subsubsection{Train/Test Split}
The dataset is split into training (70\%) and test (30\%) sets using \emph{random} selection of sequences (not sequential). This ensures that the test set is representative of the entire dataset distribution. The random split is performed with a fixed seed (42) for reproducibility.

\subsection{Force Targets}
The FT snapshot yields \((F_x, F_y, F_z, T_x, T_y, T_z)\). Current evaluations focus on the
normal component \(F_z\), which is the dominant force in vertical indentation. The absolute value of \(F_z\) is used for training to handle both positive (physical) and negative (simulation) force conventions.

\section{Machine-Learning Models}

\subsection{Force Mapping Regression}
For each stretch level, an independent Random Forest regressor approximates the mapping
\(\hat{F}_z = f_s(\mathbf{s})\). Table~\ref{tab:rf-params} summarises the training setup. In addition
to the per-stretch models, we train a \emph{combined} regressor on the pooled dataset; this provides
a single model capable of handling data from any elongation while still reporting the aggregated
KPMs.

\subsubsection{Training Configuration}
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Features:} Flattened magnetic sensor data \([S_{1x}, S_{1y}, S_{1z}, \ldots, S_{15z}]\) (45 features), normalized with \texttt{StandardScaler}.
    \item \textbf{Data split:} 70\% training, 30\% test (random split by sequence, seed=42)
    \item \textbf{Sample weighting:} Low-force samples receive higher weights to improve performance in the critical 0--1~N range
    \item \textbf{Model storage:} Each trained model is saved alongside its corresponding \texttt{scaler} (for feature normalization) to ensure consistent preprocessing during inference
\end{itemize}

\subsubsection{Metrics}
The error vector is \(e_i = F_{z,i} - \hat{F}_{z,i}\). We report:
\begin{align}
    \text{RMSE}_s &= \sqrt{\frac{1}{N} \sum_{i=1}^{N} e_i^2}, \\
    \sigma_s &= \sqrt{\frac{1}{N-1} \sum_{i=1}^{N} (e_i - \bar{e})^2},
\end{align}
which correspond to accuracy and precision for KPM~2. 

A data-driven estimate of force resolution (KPM~1) is automatically computed during training from the test set force values. The calculation proceeds as follows:
\begin{enumerate}[leftmargin=1.5em]
    \item Force values in the test set are rounded to 2 decimal places (0.01~N precision, matching FT sensor resolution)
    \item Unique force values are identified
    \item Consecutive differences between sorted unique values are computed
    \item The minimum non-zero difference is taken as \(\Delta F_{\text{min}}\)
    \item KPM1 passes if \(\Delta F_{\text{min}} \leq 0.05\)~N
\end{enumerate}
This metric is calculated for each per-stretch model and for the combined model, and is automatically included in the JSON training report.

\subsection{Press Location and Stretch Classification}
\label{sec:classification-models}

The classification pipeline consists of three components: per-stretch press location classifiers,
a global stretch classifier, and a gated pipeline that combines both.

\subsubsection{Per-Stretch Press Location Classification}
For each stretch level \(s \in \mathcal{S}\), we train a dedicated Random Forest classifier
\(\hat{p}_s(\mathbf{s})\) that maps the tactile feature vector \(\mathbf{s} \in \mathbb{R}^{45}\) to a press location label. The classifier learns the
mapping:
\[
    \hat{p}_s: \mathbf{s} \mapsto \{c_1, c_2, \ldots, c_{n_s}\},
\]
where \(c_i\) are the press location classes available for stretch \(s\) (e.g., for the single-point
dataset: \(\{\text{center}, \text{nw}, \text{ne}, \text{se}, \text{sw}\}\), and for the multi-point dataset:
\(\{\text{center}, \text{nw}, \text{ne}, \text{se}, \text{sw}, 4, 5, 6, 7, 9, 10, 11, 12\}\)).

The classifier is trained on a subset \(\mathcal{D}_s = \{(\mathbf{s}_i, p_i)\}_{i=1}^{N_s}\) where \(p_i\)
is the true press location label and all samples belong to stretch \(s\). The training objective
maximises the probability of correct classification:
\[
    \hat{p}_s = \arg\max_{\theta} \sum_{i=1}^{N_s} \log P(p_i | \mathbf{s}_i; \theta),
\]
where \(\theta\) are the Random Forest hyperparameters (see Table~\ref{tab:rf-params}).

\subsubsection{Stretch Classification}
A single Random Forest classifier \(\hat{l}(\mathbf{s})\) is trained on the pooled dataset
\(\mathcal{D}_{\text{pooled}} = \bigcup_{s \in \mathcal{S}} \mathcal{D}_s\) to predict the stretch level
from the tactile features:
\[
    \hat{l}: \mathbf{s} \mapsto \{s_1, s_2, s_3\} = \{0\%, 10\%, 20\%\}.
\]
The classifier learns to distinguish between stretch levels based on the magnetic field patterns,
which change as the skin geometry elongates. The training objective is:
\[
    \hat{l} = \arg\max_{\theta} \sum_{(\mathbf{s}_i, l_i) \in \mathcal{D}_{\text{pooled}}} \log P(l_i | \mathbf{s}_i; \theta),
\]
where \(l_i\) is the true stretch label for sample \(i\).

\subsubsection{Combined Press Location Classifier}
A global press location classifier \(\hat{p}_{\text{comb}}(\mathbf{s})\) is trained on the pooled dataset,
ignoring the stretch label. This model learns location patterns that are invariant to skin elongation:
\[
    \hat{p}_{\text{comb}}: \mathbf{s} \mapsto \{c_1, c_2, \ldots, c_n\},
\]
where the class set includes all press locations seen across all stretch levels. The training
objective is:
\[
    \hat{p}_{\text{comb}} = \arg\max_{\theta} \sum_{(\mathbf{s}_i, p_i) \in \mathcal{D}_{\text{pooled}}} \log P(p_i | \mathbf{s}_i; \theta).
\]

\subsubsection{Gated Pipeline}
The deployed pipeline uses a two-stage approach: first predict the stretch level, then route the
sample to the corresponding per-stretch press location classifier. If the predicted stretch has
insufficient training data or the per-stretch model is unavailable, the pipeline falls back to the
combined classifier:
\[
    \hat{p} = \begin{cases}
        \hat{p}_{\hat{l}(\mathbf{s})}(\mathbf{s}) & \text{if } \hat{p}_{\hat{l}(\mathbf{s})} \text{ exists and is trained}, \\
        \hat{p}_{\text{comb}}(\mathbf{s}) & \text{otherwise}.
    \end{cases}
\]

\subsubsection{Classification Metrics}
For each classifier, we report the accuracy on the test set:
\[
    \text{Accuracy} = \frac{1}{N_{\text{test}}} \sum_{i=1}^{N_{\text{test}}} \mathbb{1}[\hat{y}_i = y_i],
\]
where \(\hat{y}_i\) is the predicted class, \(y_i\) is the true class, and \(\mathbb{1}[\cdot]\) is the
indicator function. We also compute the per-class precision, recall, and F1-score:
\begin{align}
    \text{Precision}_c &= \frac{\text{TP}_c}{\text{TP}_c + \text{FP}_c}, \\
    \text{Recall}_c &= \frac{\text{TP}_c}{\text{TP}_c + \text{FN}_c}, \\
    \text{F1}_c &= \frac{2 \cdot \text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c},
\end{align}
where \(\text{TP}_c\), \(\text{FP}_c\), and \(\text{FN}_c\) are the true positives, false positives, and
false negatives for class \(c\), respectively.

\section{Key Performance Metrics}

\subsection{KPM1: Sensitivity (Force Resolution)}
\label{sec:kpm1}
KPM1 tracks the smallest distinguishable normal force when the indenter presses the skin.
During acquisition we scan forces in a quasi-static manner from 0~N to 3~N with
\SI{0.1}{\newton} increments. After the regression model is trained, the training pipeline automatically computes the minimum
non-zero separation between unique force values in the test set. The calculation is performed as follows:
\begin{enumerate}[leftmargin=1.5em]
    \item Test set force values are rounded to 2 decimal places (0.01~N precision): \(\tilde{F}_{z,i} = \text{round}(F_{z,i}, 2)\)
    \item Unique values are extracted: \(\mathcal{U} = \{\text{unique}(\tilde{F}_{z,i})\}\)
    \item Consecutive differences are computed: \(\Delta_i = |\mathcal{U}_{i+1} - \mathcal{U}_i|\)
    \item The minimum non-zero difference is taken: \(\Delta F_{\text{min}} = \min_i \{\Delta_i : \Delta_i > 0\}\)
\end{enumerate}
Benchmarks in the requirements document specify that a valid skin should resolve forces down to
\SI{0.05}{\newton} (50~mN) while maintaining a signal-to-noise ratio above 50~dB. In our reporting
we mark KPM1 as \texttt{PASS} when \(\Delta F_{\text{min}} \leq 0.05~\text{N}\); otherwise the device
fails the sensitivity target. This metric is automatically calculated and reported for each trained model (per-stretch and combined) in the JSON training report.

\subsection{KPM2: Repeatability (Accuracy \& Precision)}
KPM2 combines accuracy (low bias) and precision (low variance). We leverage the regression residuals
for this measurement: each press yields an observed force \(F_z\) and a prediction \(\hat{F}_z\).
Accuracy is described by the root-mean-square error (RMSE), while precision is captured by the
standard deviation of the residuals:
\[
    \text{Accuracy: } \text{RMSE} < 0.1~\text{N}, \qquad
    \text{Precision: } \sigma < 0.05~\text{N}.
\]
A stretch level passes KPM2 when both inequalities hold simultaneously. In practice this
operationalises the requirement: “over 90~\% of measurements must exhibit high accuracy
(\(\text{RMSE} < 0.1~\text{N}\)) and high precision (\(\text{STD} < 0.05~\text{N}\))”. The evaluation
script records a binary \texttt{kpm2\_pass} flag in the JSON report for each stretch.

\section{Data Cleaning and Training Pipeline}

\subsection{Workflow}
The complete pipeline consists of three main steps:

\subsubsection{Step 1: Data Collection}
Run the data collection script once the three stretch levels are prepared:
\begin{verbatim}
python3 src/franka_controller/franka_skin_test_single_point.py
\end{verbatim}
This script collects data for all three stretch levels (0\%, 10\%, 20\%) and saves HDF5 files in the run directory.

\subsubsection{Step 2: Data Cleaning}
After data acquisition, clean the sequences by removing outliers and the first sequence per offset:
\begin{verbatim}
python3 src/training/clean_sequences.py \
    --data-dir data/Single_Point/force_0.0to3.0N_step0.1N_single_test50
\end{verbatim}
This script:
\begin{itemize}[leftmargin=1.5em]
    \item Loads all HDF5 files from the specified directory
    \item Removes the first sequence per offset (warm-up/calibration)
    \item Removes 2 outliers per offset independently using MAD outlier detection
    \item Saves cleaned HDF5 files to \texttt{cleaned/data/} with simplified naming: \texttt{test\_XX\_YYY\_cleaned.h5}
    \item Generates raw data visualization plots in \texttt{cleaned/raw\_data/}
\end{itemize}
The cleaning process ensures that only high-quality sequences are used for training and analysis.

\subsubsection{Step 3: Model Training}
Train models using the unified training script, which works for both real and simulation data:
\begin{verbatim}
# For real data:
python3 src/training/train_unified.py \
    --data-dir data/Single_Point/force_0.0to3.0N_step0.1N_single_test50/cleaned \
    --run-label test50 \
    --feature-method raw

# For simulation data:
python3 src/training/train_unified.py \
    --h5-files data/simulation/test5/*.h5 \
    --run-label simulation_test5 \
    --feature-method raw \
    --output-dir data/simulation/test5/cleaned
\end{verbatim}

The unified training script:
\begin{itemize}[leftmargin=1.5em]
    \item Automatically detects data type (real vs simulation)
    \item Loads cleaned HDF5 files from \texttt{cleaned/data/} (real data) or directly from HDF5 files (simulation)
    \item Applies preprocessing (feature normalization, displacement filtering, Fz cutting at 3N)
    \item Removes first sequence per offset and 2 outliers per offset (already done in cleaning for real data, skipped if files are already cleaned)
    \item For simulation data: automatically segments continuous data into force cycles and maps positions to offsets
    \item Trains per-stretch and combined models (force regressors, offset classifiers, stretch classifier)
    \item Saves models to \texttt{cleaned/raw/models/}
    \item Generates confusion matrix plots and prediction plots in \texttt{cleaned/raw/plots/}
    \item Generates raw data plots (for real data: \texttt{cleaned/raw\_data/}, for simulation: \texttt{cleaned/raw/plots/sim/} with \texttt{\_sim} suffix)
    \item Generates average plots across all stretch levels
    \item Saves JSON metrics report in \texttt{cleaned/raw/models/}
\end{itemize}
The unified script ensures consistent output structure and plot generation for both real and simulation data.

\paragraph{Why Results Are Identical}
The identical performance across all three feature sets (raw, raw labelled, and raw labelled + advanced) can be explained by several factors:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Position information already present in magnetic features:} The 45 raw magnetic features inherently contain spatial location information. When force is applied at different positions (center, ne, nw, se, sw), the magnetic field patterns change because:
    \begin{itemize}[leftmargin=1.5em]
        \item Each magnetic sensor is positioned under the center of a magnet
        \item Offset positions are located at midpoints between different sensors
        \item The magnetic response varies with the position of force application
    \end{itemize}
    The Random Forest model can learn to distinguish positions from magnetic patterns alone, without explicit offset labels.
    
    \item \textbf{Feature redundancy:} Since the magnetic features are already highly discriminative for spatial location, adding explicit offset labels (raw labelled) or statistical/temporal features (advanced features) provides redundant information that does not improve the model's ability to predict force.
    
    \item \textbf{Evidence from classification accuracy:} The offset classification models achieve 99.2--100\% accuracy using only the 45 raw magnetic features (see Table~\ref{tab:offset-single}). This demonstrates that the magnetic patterns contain complete information about position. If the offset classifier can achieve near-perfect accuracy with only magnetic features, then these features are already sufficient for the force regression task, which implicitly learns position-dependent force mappings.
    
    \item \textbf{When extra features would help:} Additional features would be beneficial if:
    \begin{itemize}[leftmargin=1.5em]
        \item There were ambiguities in magnetic patterns between different positions
        \item The model had difficulty distinguishing certain positions
        \item The data were very noisy and magnetic features alone were insufficient
    \end{itemize}
    None of these conditions apply to the current dataset, where magnetic features are highly discriminative and offset classification achieves near-perfect accuracy.
\end{itemize}

\paragraph{Why Standard Deviation Remains Elevated}
The residual standard deviation (STD) remains elevated (0.07--0.09~N) across all feature sets, consistently exceeding the KPM2 threshold of 0.05~N. This can be attributed to several factors:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Physical sensor limitation:} The Robotiq FT-300S force sensor has a manufacturer-specified standard deviation of 0.1~N over a one-second period (see Table~\ref{tab:ft-specs}). The model's STD (0.07--0.09~N) is already close to this physical limit, suggesting that sensor noise is a fundamental constraint that cannot be overcome through feature engineering alone.
    
    \item \textbf{Intrinsic magnetic sensor variability:} The magnetic Hall-effect sensors exhibit inherent variability in their response. The magnetic field response can vary between sequences due to:
    \begin{itemize}[leftmargin=1.5em]
        \item Magnetic hysteresis effects
        \item Slight variations in magnet positioning
        \item Environmental factors affecting magnetic field measurements
    \end{itemize}
    
    \item \textbf{Mechanical variability:} Despite careful control, there is inherent variability in:
    \begin{itemize}[leftmargin=1.5em]
        \item Exact positioning between sequences (robot repeatability: $\pm 0.1$~mm)
        \item Silicone deformation characteristics (not perfectly reproducible)
        \item Skin tension variations between stretch configurations
    \end{itemize}
    
    \item \textbf{Model limitations:} Random Forest, while effective, may not capture all non-linearities in the force--magnetic field relationship. However, the fact that adding more features does not improve performance suggests that the limitation is not primarily due to insufficient model complexity.
\end{itemize}

The elevated STD indicates that achieving KPM2 compliance (STD $< 0.05$~N) may require improvements beyond feature engineering, such as:
\begin{itemize}[leftmargin=1.5em]
    \item More sophisticated sensor calibration and noise reduction techniques
    \item Enhanced mechanical repeatability in the experimental setup
    \item Post-processing smoothing of predictions (e.g., Savitzky--Golay filtering)
    \item Alternative model architectures (e.g., neural networks) that may better handle sensor noise
\end{itemize}

However, given the physical sensor limitation of 0.1~N standard deviation, consistently achieving STD $< 0.05$~N may be challenging without fundamental improvements to the sensor hardware or measurement methodology.

\subsection{Discussion}
\subsubsection{Key observations}
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Classification performance:} The models achieve excellent offset classification accuracy (99.2--100\%), demonstrating that spatial features are highly discriminative. Stretch classification also performs well (99.4\%), confirming that the magnetic field patterns change reliably with skin elongation.
    \item \textbf{Force regression performance:} The models achieve RMSE values ranging from 0.07~N (20\% stretch) to 0.09~N (0\% stretch), with the combined model achieving 0.08~N. While KPM1 passes (force resolution \(\leq 0.05\)~N), KPM2 fails due to residual standard deviation exceeding 0.05~N. The RMSE values are close to the KPM2 threshold of 0.10~N, indicating good model performance.
    \item \textbf{Feature engineering impact:} Extensive feature engineering (adding offset labels and statistical/temporal features) does not improve force regression performance. All three feature sets (raw, raw labelled, raw labelled + advanced) achieve identical metrics, confirming that the base 45 raw magnetic features already contain sufficient information for accurate force prediction. This is supported by the near-perfect offset classification accuracy (99.2--100\%) achieved using only magnetic features.
    \item \textbf{Standard deviation limitation:} The residual standard deviation (0.07--0.09~N) remains elevated across all feature sets, primarily due to the physical limitation of the FT-300S sensor (0.1~N standard deviation specification). This suggests that achieving KPM2 compliance (STD $< 0.05$~N) may require improvements beyond feature engineering, such as sensor calibration, mechanical repeatability enhancements, or post-processing smoothing techniques.
    \item \textbf{Stretch level dependency:} Performance improves with increasing stretch level, with 20\% stretch showing the best RMSE (0.07~N). This may indicate that increased skin tension provides more consistent sensor responses.
    \item \textbf{Cleaned dataset structure:} The organized \texttt{cleaned/} directory structure (data/, raw/models/, raw/plots/, raw\_data/) enables easy access to all processed data, trained models, and visualizations in a single location, improving reproducibility and data management.
    \item \textbf{Force precision:} Force values are rounded to 0.01~N precision (2 decimal places) to match the FT sensor resolution, ensuring realistic force resolution calculations and removing artificial precision artifacts.
\end{itemize}

\section{Simulation Dataset Evaluation}
\label{sec:simulation}

\subsection{Dataset Description}
Alongside the on-robot acquisitions, the simulation team supplied HDF5 dumps emulating the
single-point protocol. Two datasets are available: \textbf{test2} (early validation) and \textbf{test5} (latest).
Each file corresponds to a stretch level (0, 10, 20\%) and contains:
\begin{itemize}[leftmargin=1.5em]
    \item \texttt{MagneticField}~\((N, 15, 3)\): raw \(B_x, B_y, B_z\) readings for the \(3\times5\) sensor grid.
    \item \texttt{IdenterPosition}~\((N, 3)\): tool pose in metres. The pipeline rounds the \(x\) and \(y\)
          coordinates to 0.1~mm to derive discrete contact labels. Positions are mapped to offsets (center, ne, nw, se, sw) based on their \emph{relative} position to the center, enabling correct classification across different stretch levels.
    \item \texttt{forcesTest}~\((N, 3)\): Cartesian forces (Fx, Fy, Fz) sampled at the same rate as the
          magnetic field. Forces are negative (0 to -3~N) in simulation, so absolute values are used during training, with the negative sign restored during plotting.
    \item Optional attributes: \texttt{stretch} (percentage) and \texttt{YoungModulus}, which the trainer
          parses to enrich the metrics JSON.
\end{itemize}

\subsubsection{Test5 Dataset (Latest)}
The test5 dataset contains continuous force cycles concatenated per position. The training pipeline automatically segments these into individual sequences based on force cycles (0N $\rightarrow$ 3N $\rightarrow$ 0N). The raw exports reside in \texttt{data/simulation/test5/}. 

\paragraph{Sequence Segmentation and Position Mapping}
The simulation data processing pipeline performs three key steps:

\begin{enumerate}[leftmargin=1.5em]
    \item \textbf{Position Detection:} For each sample, the pipeline extracts X,Y coordinates (in metres) from the \texttt{IdenterPosition} dataset and converts them to millimetres, rounding to 0.1~mm resolution. This creates discrete position labels (e.g., \texttt{x+05.5mm\_y+02.5mm}) that group samples with similar coordinates. For test5, five unique positions are detected:
    \begin{itemize}[leftmargin=1.5em]
        \item \texttt{x+00.0mm\_y+00.0mm} (center)
        \item \texttt{x+05.5mm\_y+02.5mm} (southeast)
        \item \texttt{x+05.5mm\_y-02.5mm} (southwest)
        \item \texttt{x-05.5mm\_y+02.5mm} (northeast)
        \item \texttt{x-05.5mm\_y-02.5mm} (northwest)
    \end{itemize}
    
    \item \textbf{Offset Mapping:} The pipeline identifies the center position (closest to origin) and maps other positions to offsets based on their \emph{relative} position to center:
    \begin{itemize}[leftmargin=1.5em]
        \item \textbf{ne (northeast):} $dx < 0$ and $dy > 0$ (negative X, positive Y)
        \item \textbf{nw (northwest):} $dx < 0$ and $dy < 0$ (negative X, negative Y)
        \item \textbf{se (southeast):} $dx > 0$ and $dy > 0$ (positive X, positive Y)
        \item \textbf{sw (southwest):} $dx > 0$ and $dy < 0$ (positive X, negative Y)
    \end{itemize}
    This relative mapping ensures correct offset assignment across different stretch levels, where absolute coordinates may vary but relative positions remain consistent.
    
    \item \textbf{Force Cycle Segmentation:} For each position, the pipeline identifies complete force cycles:
    \begin{itemize}[leftmargin=1.5em]
        \item \textbf{Start:} Force rises above 0.2~N (from $< 0.2$~N)
        \item \textbf{Peak:} Force reaches $> 2.5$~N
        \item \textbf{End:} Force drops below 0.2~N (after reaching peak)
        \item \textbf{Minimum duration:} At least 50 samples (0.5~s at 100~Hz)
    \end{itemize}
    Each valid cycle becomes a separate sequence. For test5, this results in approximately 29 sequences per offset (145 total sequences per stretch level).
\end{enumerate}

\paragraph{Training Invocation}
The unified training script can be used for both real and simulation data:
\begin{verbatim}
python3 src/training/train_unified.py \
    --h5-files data/simulation/test5/*.h5 \
    --run-label simulation_test5 \
    --feature-method raw \
    --output-dir data/simulation/test5/cleaned
\end{verbatim}
This creates a processed dataset under \texttt{data/simulation/test5/cleaned/} with the same structure as real data:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Automatic cycle segmentation:} Continuous data is segmented into individual force cycles
          (0N $\rightarrow$ 3N $\rightarrow$ 0N). Each cycle must have a minimum duration (50 samples) and reach
          a peak force above 2.5~N to be considered valid.
    \item \textbf{Sequence downsampling:} Sequences are downsampled to match physical data length (81 samples average)
          using linear interpolation.
    \item \textbf{Outlier removal:} By default, outliers are \emph{not} removed for simulation data. Use the
          \texttt{--remove-outliers} flag to enable outlier removal (2 per offset independently, same as physical data).
    \item \textbf{Dataset balancing:} Sequences are balanced across stretch levels if counts differ.
    \item \textbf{Offset mapping:} Positions are mapped to offsets (center, ne, nw, se, sw) based on relative
          positions to center, enabling correct classification across different stretch levels.
    \item \textbf{Raw data plots:} All raw data plots are generated and saved in \texttt{cleaned/raw/plots/sim/stretch\_XXXpct/}
          with a \texttt{\_sim} suffix to distinguish them from real data plots.
\end{itemize}

\subsection{Simulation Results}

\subsubsection{Test5 Dataset Results}
Table~\ref{tab:sim-force-test5} and Table~\ref{tab:sim-offset-test5} summarise the baseline models trained on the
test5 simulation dataset using the unified training script. The dataset contains continuous force cycles that are automatically segmented into
individual sequences (approximately 29 sequences per offset, 145 total sequences per stretch level).
The simulation data uses the same preprocessing pipeline as the physical data: raw 45 features, displacement filtering,
Fz cutting at 3N, and sequence downsampling to match the average length of physical data sequences (81 samples).
By default, outliers are \emph{not} removed for simulation data (unlike physical data), allowing all sequences to be used for training.
The unified training script ensures consistent output structure and plot generation for both real and simulation data.

displacement filtering, Fz cutting at 3N, and outlier removal (if \texttt{--remove-outliers} flag is used). Sequences are downsampled to match the average length of
physical data sequences (81 samples), and duplicated to reach 150 sequences per stretch level for balanced training.

\subsubsection{Where to find the artefacts}
The unified training script outputs all joblib models inside \texttt{cleaned/raw/models/}, while the accompanying JSON metrics are saved as \texttt{\{run\_label\}\_metrics.json} in the same folder. All plots are saved in \texttt{cleaned/raw/plots/} (with \texttt{sim/} subdirectory and \texttt{\_sim} suffix for simulation data). This structure mirrors the one used for real data, ensuring consistent access patterns for evaluation utilities and GUIs.
